## Назначение

Семантический анализ проверяет программу после построения AST.

## Аннотирование AST

Каждый `ASTNode` может хранить выведенный тип:

```cpp
std::optional<TypeDescriptor>
```

Семантический анализатор записывает типы в существующие AST-узлы через `SetInferredType`.

## Таблица символов

`SymbolTable` хранит соответствие имени и семантического символа. Символ содержит имя, тип, вид символа, для функций - типы параметров, для struct-типов - список полей и методов.

Виды символов:

- `VARIABLE`;
- `FUNCTION`;
- `BUILTIN_FUNCTION`;
- `TYPE`.

Идентификатор должен быть определён до использования. `:=` и `var` создают символы в текущей области видимости.

Top-level struct declaration создаёт символ вида `TYPE`:

```cetus
type Point struct {
    x int;
    y int;
}
```

После этого имя `Point` можно использовать как тип в объявлении переменной, параметра функции, возвращаемого значения и элемента массива:

```cetus
var point Point;
var points [2]Point;
```

Если type name не разрешается в символ `TYPE`, semantic analyzer выдаёт диагностику неизвестного типа.

## Области видимости

Блок создаёт новую область видимости. Поиск идентификатора начинается в текущей области и продолжается во внешних областях.

Идентификатор, созданный внутри блока, недоступен после выхода из блока.

`:=` создаёт новый символ в текущей области. Если имя уже объявлено в текущей области, это семантическая ошибка. Если имя существует только во внешней области, внутреннее объявление скрывает внешнее имя.

Пользовательские функции, параметры функций и переменные не могут использовать зарезервированные callable-имена и имена пользовательских типов. Зарезервированными callable-именами считаются имена встроенных функций и другие имена, занятые вызываемыми символами.

## Shadowing

Shadowing разрешён только между разными областями видимости: объявление в локальном блоке может скрыть символ из внешнего блока.

```cetus
func main() {
    value := 1;
    if true {
        value := 2;
        printf(value);
    }
    printf(value);
}
```

Внутри `if` имя `value` ссылается на внутреннюю переменную. После выхода из блока `if` имя снова ссылается на внешнюю переменную.

Повторное объявление имени в той же области видимости запрещено:

```cetus
func main() {
    value := 1;
    value := 2;
}
```

Такой код должен давать диагностику `Variable is already declared in current scope: value`.

Для множественного объявления правило применяется к каждому имени в текущей области видимости. Если хотя бы одно имя уже объявлено в текущем scope, для него добавляется диагностика дубля. Имена из внешних scope не считаются дублями и могут быть скрыты локальным объявлением.

## Проверка типов

Проверка выполняется для:

- литералов;
- идентификаторов;
- унарных выражений;
- бинарных выражений;
- присваиваний;
- объявлений переменных;
- expression statements;
- списков операторов;
- `if`;
- `return`;
- объявлений функций;
- объявлений struct-типов;
- объявлений методов;
- вызовов функций.

Struct declaration проверяется на дубли имён полей и корректность типов полей. Повтор поля в одном struct является семантической ошибкой.

## Условия

Условие `if` должно иметь truthy-compatible тип: `int` или `bool`.

Если `if` содержит `else`, обе ветки анализируются. `if` имеет тип `void`; типы веток не обязаны совпадать.

Операторы объявления, присваивание, expression statement, `if`, `return`, блок и список операторов имеют тип `void`.

Expression statement может иметь тип `void`. Остальные value-контексты требуют выражение-значение. `void` не допускается как initializer переменной, правая часть присваивания, аргумент функции, значение `return`, условие `if`, операнд унарного или бинарного оператора.

`return` вне функции является семантической ошибкой.

Внутри функции `return;` разрешён только для `void`-функций. `return expr;` должен совпадать с типом возврата функции.

Функция с не-`void` типом возврата должна гарантированно возвращать значение. Список операторов гарантирует возврат, если один из его операторов гарантирует возврат. `if` гарантирует возврат только при наличии `else`, когда обе ветки гарантируют возврат.

Оператор после гарантированного возврата в том же списке операторов является недостижимым кодом. Семантический анализатор добавляет диагностику для недостижимого оператора, но продолжает анализировать его содержимое.

Параметры функции добавляются в область видимости тела функции как локальные переменные. Повтор имени параметра в одной функции является семантической ошибкой.

Программа должна объявлять entry point `main`. `main` должна разрешаться в пользовательскую функцию верхнего уровня, не иметь параметров и возвращать `void`. Встроенная функция не может быть entry point.

Перед проверкой операторов программы семантический анализ регистрирует struct-типы, сигнатуры функций верхнего уровня и методы. Это позволяет использовать пользовательские типы, функции и методы ниже по файлу, а также проверять рекурсивные и взаимно рекурсивные объявления.

Метод хранится в method table соответствующего `TYPE`-символа и дополнительно регистрируется как callable symbol с qualified name:

```text
Point.Sum
```

Method call `p.Sum()` разрешается через тип receiver `p`, а codegen передаёт receiver первым аргументом в callable `Point.Sum`.

Если метод объявлен с pointer receiver:

```cetus
func (p *Point) Move() {
}
```

то method call `p.Move()` требует assignable identifier receiver. Codegen передаёт receiver как runtime reference, чтобы метод мог менять исходное значение.

Вызов функции проверяется по символу функции. Имя должно разрешаться в `FUNCTION` или `BUILTIN_FUNCTION`.

Для пользовательской функции количество аргументов должно совпадать с количеством параметров, тип каждого аргумента должен совпадать с типом соответствующего параметра.

Для встроенной функции применяются правила конкретной встроенной функции.

`print`, `println`, `printf`, `len` и `read*` являются встроенными функциями. Их сигнатуры описаны в `docs/spec/standard-library.md`. `printf` является compatibility alias для `println`.
